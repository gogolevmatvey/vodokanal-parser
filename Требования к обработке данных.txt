================================================================================
ЗАДАНИЕ НА ОБРАБОТКУ ДАННЫХ ЕРИЦ (ЖКХ)
================================================================================

ФОРМАТ ДАННЫХ ПО ПОЗИЦИЯМ В СТРОКЕ (разделитель - символ ';'):
--------------------------------------------------------------------------------
1. Номер лицевого счета
2. ФИО плательщика
3. Адрес (разделитель внутри адреса - запятая)
   3.1. Населенный пункт
   3.2. Улица
   3.3. Дом
   3.4. Квартира (может отсутствовать или присутствовать во множественном числе)
4. Период начисления
5. Вариативно:
   5(а). Сумма начисления
   5(б). Пары полей:
        5(б).1. Прибор учета
        5(б).2. Показания прибора учета

Количество пар полей типа 5(б) может быть произвольным (от 1 до n).

================================================================================
ПРАВИЛА ВАЛИДАЦИИ
================================================================================

В случае, когда строка не удовлетворяет указанному выше формату, она не должна
попасть в базу данных, а должна быть записана в отчет об ошибках.

ОБЯЗАТЕЛЬНЫЕ ТРЕБОВАНИЯ:
1. Номер лицевого счета должен состоять только из цифр
2. ФИО плательщика не должно быть пустым
3. Адрес должен содержать минимум 3 запятые (населенный пункт, улица, дом, квартира)
4. Период начисления должен быть числом (2-4 цифры)
5. Сумма начисления должна быть числом
6. Показания счетчиков должны быть числами (целыми или дробными)

================================================================================
ПРАВИЛА ИСПРАВЛЕНИЯ ОШИБОК
================================================================================

ФИО ПЛАТЕЛЬЩИКА:
--------------------------------------------------------------------------------
- Если поле ФИО полностью отсутствует (пустая строка между разделителями) →
  вставляем "данные отсутствуют"
- Если ФИО содержит любые символы (даже "*", цифры, пробелы) → исправляем на
  "данные отсутствуют" (считаем маскированием персональных данных)

Примеры:
  Было: 900001001;;Киржач г, Мира ул, 9, 0;519;120.50;
  Стало: 900001001;данные отсутствуют;Киржач г, Мира ул, 9, 0;519;120.50;

  Было: 900001002;.*  ;Кольчугино г, Инициативная ул, 19, 21;519;435.52;...
  Стало: 900001002;данные отсутствуют;Кольчугино г, Инициативная ул, 19, 21;519;435.52;...

  Было: 900001003;Юрьевец мкр, Гвардейская ул, 15, 159;519;268.45;
  Стало: 900001003;данные отсутствуют;Юрьевец мкр, Гвардейская ул, 15, 159;519;268.45;
  (ФИО отсутствовало, адрес был на его месте)

АДРЕС:
--------------------------------------------------------------------------------
Адрес должен содержать 4 части, разделенные запятыми:
  1. Населенный пункт
  2. Улица
  3. Дом
  4. Квартира

Если меньше 3 запятых в адресе → определяем, какие части есть, и добавляем
недостающие с пометкой "не указан":

  • 0 запятых (1 часть): "Населенный пункт, Улица не указана, Дом не указан, Квартира не указана"
  • 1 запятая (2 части): "Населенный пункт, Улица, Дом не указан, Квартира не указана"
  • 2 запятые (3 части): "Населенный пункт, Улица не указана, Дом, Квартира"
    (если 3-я часть - число, считаем это домом с квартирой)
  • 2 запятые (3 части): "Населенный пункт, Улица, Дом, Квартира не указана"
    (если 3-я часть не число, считаем это домом)

Если больше 5 запятых (много квартир) → объединяем квартиры через пробел

Примеры:
  Было: 900001010;Иванов И.И.;Сокол п, 7, 4;519;593.56;...
  Стало: 900001010;Иванов И.И.;Сокол п, Улица не указана, 7, 4;519;593.56;...
  (добавлена "Улица не указана", 7 - дом, 4 - квартира)

  Было: 900001011;Петров П.П.;Сокол п, 8, 37;519;120.01;
  Стало: 900001011;Петров П.П.;Сокол п, Улица не указана, 8, 37;519;120.01;
  (добавлена "Улица не указана")

  Было: 900001012;Сидоров С.С.;Гусь-Хрустальный г, Перегрузочная ул, 5а, 80,81,82,83;519;128.34;
  Стало: 900001012;Сидоров С.С.;Гусь-Хрустальный г, Перегрузочная ул, 5а, 80 81 82 83;519;128.34;
  (квартиры объединены через пробел)

  Было: 900001013;Кузнецов А.А.;Беречино, 182, ,;519;59.69;
  Стало: [НЕ ИСПРАВЛЯЕТСЯ] Пустая часть адреса - требует ручного вмешательства

ПЕРИОД НАЧИСЛЕНИЯ:
--------------------------------------------------------------------------------
- Если текстовый формат (май.00, янв.40 и т.п.) → заменяем на "0"
- Если пустой → заменяем на "0"

СУММА НАЧИСЛЕНИЯ:
--------------------------------------------------------------------------------
- Если неправильный формат (текст вместо числа) → заменяем на "0"
- Если отрицательная сумма → это перерасчет, оставляем как есть
- Если текстовый месяц (сен.74, фев.58) → заменяем на "0"

Примеры:
  Было: 900001020;Смирнов В.В.;Муром г, Центральная ул, 16, 1;519;сен.74;...
  Стало: 900001020;Смирнов В.В.;Муром г, Центральная ул, 16, 1;519;0;...

  Было: 900001021;Попов Д.Д.;Суздаль г, Нижегородская ул, 29, 0;519;июн.87;
  Стало: 900001021;Попов Д.Д.;Суздаль г, Нижегородская ул, 29, 0;519;0;

ПОКАЗАНИЯ СЧЕТЧИКОВ:
--------------------------------------------------------------------------------
- Если текстовый месяц вместо показаний (май.00, янв.40 и т.п.) → заменяем на "0"
- Если неправильный формат → заменяем на "0"

Примеры:
  Было: 900001030;Васильев Е.Е.;Ковров г, Никольская ул, 43, 0;519;120.01;3300000001 ХВС;май.00;
  Стало: 900001030;Васильев Е.Е.;Ковров г, Никольская ул, 43, 0;519;120.01;3300000001 ХВС;0;

  Было: 900001031;Новиков Н.Н.;Клементьево с, Посадского ул, 17, 2;519;48.45;3300000002 ХВС;70.0000;3300000003 полив;янв.40;
  Стало: 900001031;Новиков Н.Н.;Клементьево с, Посадского ул, 17, 2;519;48.45;3300000002 ХВС;70.0000;3300000003 полив;0;

ВЫХОДНЫЕ ФАЙЛЫ
================================================================================

1. valid_records.txt - валидные записи (без ошибок)
2. invalid_records.txt - записи с ошибками + причина ошибки
3. corrected_records.txt - исправленные записи (были ошибочными, стали валидными)
4. uncorrected_records.txt - неисправленные ошибки (требуют ручного вмешательства)
5. error_report.txt - отчет со статистикой по типам ошибок
